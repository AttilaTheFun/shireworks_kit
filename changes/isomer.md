- Shireworks Kit on Isomer's hosts (Android): every library builds there, so an app's Android build links `ShireworksKit` and puts the same `.shireworks()` on its root view. There it gives Report a Bug: `ShakeKitReportButton` and `ShakeReport.request()` open the report in `.shakeToReport`'s sheet, without a shake, screenshot or logs until Isomer has them (`.onShake`, its screenshot API); the issue says the logs weren't read (`LogSource.omission`, `ShakeReport.logsOmission`, `AppLogSource.notRead`). Crashes and updates stay Apple's systems' (`.shireworks()` starts them, which does nothing there). ShireworksShake reads logs (`OSLogStore`) on Apple's systems alone, and hears requests through Foundation's notifications (one observer, `ReportPresenters`) in place of Combine's publisher; `ShakeKitCommands` and the report window stay Apple's. ShireworksUpdates' release checks use a plain URLSession on Isomer's Foundation, which has no delegates or cache.
- `.shakeToReport(repository:configuration:credentials:)`: a sign-in of the host's own to file with, in place of the shared one (for a host without one, Isomer's for now). `ShakeReport.isOffered` is true on Isomer's hosts.
